火山方舟 Agent Plan 与 Coding Plan：选套餐、接模型，把费用边界配清楚

2026年9月8日 · 阅读需 27 分钟
ChatArch

买了大模型套餐，最需要确认的不是客户端能否返回一句话，而是：这句话调用了哪个模型，走了哪条入口，消耗的是套餐额度还是账户余额。

火山方舟的 Coding Plan 和 Agent Plan 都能接入 AI 工具，也都出现 OpenAI、Anthropic、API Key 等熟悉的配置项，但它们的密钥、地址、模型范围和超额行为并不相同。尤其是 Agent Plan，即使没有改过 Base URL 和 Key，开启超额后付费后也可能产生现金账单。[1][3][4]

本文按实际使用顺序展开：先决定用途和套餐，再选模型、配置入口，最后确认限流与费用。资料核查日期为 2026 年 9 月 8 日；内容来自官方公开文档，未登录账号、未购买套餐、未进行模型或媒体生成实测。价格和模型列表是该日期的快照，实际购买资格与账号额度以控制台为准。

先判断用途：这是工具订阅，不是通用 API 余额包​

Coding Plan 面向个人编码工作，核心是让开发者在 Claude Code、OpenCode 等支持的工具中使用多种模型；Agent Plan 把能力扩展到图片、视频、语音及平台配套服务，并用 AFP 统一计量。Agent Plan 也能写代码，Coding Plan 也有 Agent 工具接入；不能只凭产品名字划分用途。[1][2]

你主要想做什么建议先看什么原因
在编码工具中读代码、改代码、调试Coding Plan Lite / Pro以编码工作量选档，避免为暂时不用的能力做复杂配置
在 AI 工具中同时使用文字、图片、语音、搜索Agent Plan Small / Medium支持更广的能力，用 AFP 看清各类资源消耗
使用 Seedance 2.0 系列视频生成Agent Plan Large / Max当前权益表把这一系列列在 Large、Max 中
给产品后端、批处理或长期自动任务供应模型普通方舟模型 API，或取得适用的明确授权不应把个人工具订阅改造成通用 API 服务
多人使用或处理不适合进入个人版数据授权范围的内容企业版，另行核对合同与使用场景席位、数据政策和个人版不同

前两行是选型建议，不是性价比实测排名；模型和使用范围依据官方概览及条款。[1][2][28]

“兼容 OpenAI API”描述的是请求协议，不代表允许任意用途。服务专用条款要求在支持或认可的工具中，以最终用户交互式调用为主；对后台服务、批处理、定时任务、第三方共享或转售等场景设有限制，明确支持或另行授权的场景除外。Agent Plan 的文本与向量化权益也明确写有“不可用于 API 调用”的使用限制。[2][28]

这与官方提供图片、视频、语音的 API 接入示例并不需要二选一理解：媒体能力有官方给出的专用接入路径，但不能据此把整个套餐推定为不限用途的模型后端。 接入 AI 工具是一条路线；经营对外服务是另一条路线，后者应单独核对授权和计费。[26][27][28]

套餐多少钱，买到的额度怎样使用​

Coding Plan：Lite 和 Pro​

官方活动规则列出的个人版原价为 Lite 40 元/月、Pro 200 元/月。在 2026 年 6 月 8 日至 11 月 8 日活动期间，符合资格的用户最多可享前两个月 Lite 9.9 元/月、Pro 49.9 元/月；第三个月恢复原价，名额和优惠资格有限，新购、续费、升配共享资格。这不是长期固定价格。[37]

档位标准月价当前官方定位
Lite40 元中等强度开发
Pro200 元复杂项目、高强度开发

Coding Plan 当前概览没有给出一张可作为承诺的“每月固定请求次数”或“固定 token 数”表。实际消耗受模型、上下文长度、思考过程和多 Agent 工作方式影响，不能把旧活动页的估算次数当成现在的合同额度。[1]

它有 5 小时、周、订阅月三层额度：5 小时从首次请求起计；周额度每周一零点刷新；月额度在每个订阅月的首日零点刷新。同一套餐在不同支持工具间共享额度。正确使用套餐入口时，周期额度耗尽后等待恢复，不消耗其他资源包或账户余额。[1]

Agent Plan：用 AFP 统一计量​

AFP 是 Agent Fuel Point，官方中文称“Agent 燃料值”。它是套餐内部统一消耗单位，不是 token，也不是人民币。[2][10]

个人版档位标准月价月额度 AFP周额度 AFP5 小时额度 AFP
Small40 元20,0007,0002,000
Medium200 元100,00035,00010,000
Large500 元250,00087,50025,000
Max1,000 元500,000175,00050,000

这些窗口是同时约束，不是几份可以相加的额度。月额度尚有余量，也可能先碰到 5 小时或周额度。[2]

Small、Medium 在同一活动周期内也有前两个月 9.9 元、49.9 元的优惠，限制条件见活动页。同价不等于同量：Coding Plan 没有公开到足以与 AFP 做严格等价换算的额度规则，不能由价格推导两个套餐的实际编码量完全相等。[1][22][37]

图片、视频、语音及 Harness 不受 5 小时、周额度限制；概览还给出部分能力的日额度，数值为套餐月额度的一半。不过，日额度到底覆盖哪些能力，概览不同段落存在不一致，下文会单列这个问题。[2]

AFP 怎样变成一次实际消耗​

文本和向量化模型的公式为：[10]

AFP = (输入 token × 输入抵扣系数 + 输出 token × 输出抵扣系数) / 10,000

当前表中各文本模型的输入、输出系数相同，但不同模型差异很大。下表同时列出模型选择和 AFP，便于把“能力选择”与“资源消耗”放在一起看；这些是平台公布的计量参数，不是模型质量排名。[10]

假设 doubao-seed-2.1-turbo 一次请求输入 50,000 token、输出 500 token，系数为 2.5，代入公式为 12.625 AFP。这是按文档公式计算的示例，不是本次账号实测。图片、语音则采用不同的计量基准：[10]

能力套餐内计量示例
doubao-seedream-5.0-lite成功生成一张图片：99 AFP
doubao-seed-tts-2.0每万字符 1,350 AFP；2,000 字符为 270 AFP
doubao-seed-asr-2.0每小时语音 450 AFP
豆包搜索抵扣系数 5 AFP/次；概览另列每月 500 次免费额度

套餐里还包括专业数据集、Agent 记忆、AI Native 应用开发底座、Agent 进化等 Harness，也就是平台配套的工具和服务能力。它们不都是按“问一次”计费：有的按文件规模、计算或存储时长消耗；不用模型的时段也未必完全不消耗 AFP。[2][10]

尤其不要随意开关记忆服务：官方写明，开启 Agent Plan 抵扣会覆盖账号下 OpenViking 的所有数据库；关闭抵扣会立即关停相应商品，并可能清理数据。关超额后付费与关服务抵扣不是同一个动作。[10]

能用哪些模型：公共清单与具体账号分开看​

以下是个人版公开文档的模型快照。Coding Plan 明确列出 9 个具名文本模型，另支持 doubao-embedding-vision；Agent Plan 权益表列出 19 个具名模型，包括文本、向量、图片、视频和语音。Auto 是路由模式，不再算作一个独立模型；Harness 也不计入模型数量。[1][2][7]

直接填模型名，还是填 ark-code-latest​

两款套餐的官方示例都支持 ark-code-latest 这种控制台管理方式。它不是某个模型的固定版本：客户端保持这个名称，实际选择在套餐控制台中调整。直接填写具名模型 ID，则便于在客户端明确选择模型。[3][7]

我的建议是：需要复现和排错时优先填具名模型；希望由控制台统一管理、接受自动路由变化时再用别名。 即使采用具名 ID，像 Evolving 这样的持续更新模型也不能当成永久冻结的版本。[1]

还要区分“直接选择 Kimi K3”与“Auto 内部可能路由到 Kimi K3”：Agent Plan 的活动说明写有 Auto 抵扣系数 0.5、支持路由到 Kimi K3，但不能把这一规则改写成 Small 可以任意直接指定 Kimi K3。[2][10]

配置入口：Key、协议和地址必须成套匹配​

先拿对 Key​

用途应使用的凭据获取位置

Agent Plan 个人版调用Agent Plan 专属 API Key开通管理 → Agent Plan

查询身份、套餐和账单等管控操作AK/SK；采用临时凭据时还需 STS tokenIAM 访问控制，按最小权限授权

个人 Coding 与 Agent 的密钥获取路径分别见快速开始；企业版使用席位 Key，不要套用个人 Coding 的规则。[3][7][29][30]

Coding Plan 个人版的 Key 本身不是“只准花套餐”的保险锁：同一方舟 Key 若具备普通模型调用权限，而客户端误填普通 API 地址，就可能走按量计费。Key 正确、地址错误，仍然可能扣错地方。 Agent Plan 文档则明确要求它自己的专属 Key，其他方舟 Key（包括 Coding 所用 Key）不能混用。[3][7]

可直接打开的官方入口：

  • Coding Plan 订阅：https://www.volcengine.com/activity/codingplan
  • Coding 个人版 API Key：https://console.volcengine.com/ark/region:cn-beijing/apikey
  • Agent Plan 套餐及专属 Key：https://console.volcengine.com/ark/region:cn-beijing/openManagement?LLM=%7B%7D&OpenModelVisible=false&advancedActiveKey=agentPlan

不要把 AK 的 Access Key ID 填进模型工具的 API Key 输入框。AK/SK 是签名凭据对，只有 ID 不能完成签名；API Key 通常用于数据面调用，不能替代这些仅支持 Access Key 的管控接口。[6][16][24][33]

Coding 地址来自快速开始；Agent 的 Anthropic 地址来自快速开始，OpenAI 地址可在 OpenCode 和媒体接入文档中确认。[3][7][14]

普通方舟按量调用常用的 https://ark.cn-beijing.volces.com/api/v3 不在这张套餐表里。Coding 快速开始明确提醒，这个地址不消耗 Coding Plan 额度，而会产生额外费用。[7]

填写的是工具要求的 Base URL，不要凭习惯把所有地址都改成 /v1，也不要在只要求 Base URL 的字段里随手追加 /chat/completions。协议兼容不代表路径可以互换。

Chat Completions 和 Responses：两种都支持​

两款套餐都明确支持 Chat Completions API 与 Responses API，不是只支持前者。官方 OpenCode 文档推荐 Responses 配置；这是平台的建议，不是本文做过两种协议效果对比的结论。[14][38]

套餐Chat Completions 完整请求地址Responses 完整请求地址
Coding Planhttps://ark.cn-beijing.volces.com/api/coding/v3/chat/completionshttps://ark.cn-beijing.volces.com/api/coding/v3/responses
Agent Planhttps://ark.cn-beijing.volces.com/api/plan/v3/chat/completionshttps://ark.cn-beijing.volces.com/api/plan/v3/responses

表中是完整请求地址；在只要求 Base URL 的工具中，仍填写上一表的公共前缀，让 SDK 自动追加路径。这里的 Chat Completions 是 /chat/completions，不是旧版单独的 /completions。[14][38]

  • Codex CLI：两款套餐官方示例均设置 wire_api = "responses"，可以使用支持该配置的最新版客户端。[39][40]
  • OpenCode："npm": "@ai-sdk/openai" 使用 Responses；"npm": "@ai-sdk/openai-compatible" 使用 Chat Completions。仅填相同 Base URL，并不能决定最终走哪种协议。[14][38]
  • Claude Code：使用 Anthropic 兼容入口，不把它归入这两个 OpenAI 接口。[3][7]

这段说明针对套餐的文本模型接入。图片生成、视频、语音仍有独立接口，不能由“两种协议都支持”推导为所有媒体能力都可以通过聊天请求调用。[26][27]

从零接入一次：先只配一个客户端​

  1. 确定个人版还是企业版，阅读数据条款后按需订阅。
  2. 从对应入口获取 Key，不在聊天、截图、仓库或 shell 历史里留真实值。
  3. 查看客户端使用的是 OpenAI 还是 Anthropic 协议，选择上表对应地址。
  4. 首次选择一个套餐明确支持的具名文本模型，或按官方说明用 ark-code-latest。
  5. 检查客户端是否还留有旧的 provider、环境变量和按量 fallback。
  6. 仅在准备消费额度时进行一条短交互，再核对实际 provider、模型和用量；不要一开始就开多 Agent 或批量任务。

前四步是官方接入配置的整理；后两步是降低排错复杂度和误付费风险的建议。[3][7]

以 Claude Code 为例，下面两组参数二选一。[REDACTED] 只是占位符，应在本地安全配置中替换，不能直接照抄当成有效 Key。这里不执行安装、不启动客户端，也不发送推理请求。[3][7]

Coding Plan 个人版：

ANTHROPIC_BASE_URL=https://ark.cn-beijing.volces.com/api/coding
ANTHROPIC_AUTH_TOKEN=[REDACTED]
ANTHROPIC_MODEL=ark-code-latest

Agent Plan 个人版：

ANTHROPIC_BASE_URL=https://ark.cn-beijing.volces.com/api/plan
ANTHROPIC_AUTH_TOKEN=[REDACTED]
ANTHROPIC_MODEL=ark-code-latest

OpenCode 等客户端则按其 provider 配置填写相应的 baseURL、apiKey 和模型 ID。具体字段属于客户端，不要把 Claude Code 的环境变量名当成所有工具通用的配置规范。[14]

图片、视频和语音是另外的接口族​

Agent Plan 不意味着所有能力都塞进一条聊天接口。图片使用专用生成接口；视频通常是创建任务后再查询任务状态；语音有独立域名、HTTP 或 WebSocket 协议和请求头。[26][27]

图片和视频使用 Agent Plan 专属 Key；语音文档要求把同一类专属 Key 放在 X-Api-Key，并配置 X-Api-Resource-Id：TTS 为 seed-tts-2.0，ASR 为 volc.seedasr.sauc.duration。语音不能简单照搬 OpenAI 的 Bearer 请求头和路径。[26][27]

这些是官方接入契约，不是本文实测成功的声明。客户端是否已集成相应媒体能力，还需按它自己的插件或工具文档确认。

控费用：不是只看账户里有没有套餐​

Coding Plan 与 Agent Plan 的超额行为不同​

Coding Plan 公开规则是周期额度耗尽后等待刷新；前提是使用正确套餐入口和支持的模型。它不会替你拦住客户端转到另一个按量 provider 的行为。[1][7]

Agent Plan 可以对支持的模型、Harness 开启超额后付费。开启后，文本和向量化在碰到 5 小时、周或月额度时，就可能继续调用并产生后付费账单；不必等到月额度全部用完。对应额度刷新后再优先抵扣套餐。语音和 Harness 的超额触发按文档是月额度，不受 5 小时和周窗口约束。[2][4]

也不是所有模型都能超额继续用：当前规则列出部分文本模型、向量化、TTS、ASR支持；Auto、图片、视频和若干文本模型不支持。kimi-k2.7-code 出现在套餐模型表中，但当前超额表没有对应项，不能擅自补成支持或不支持。[2][4]

语音超额价格在规则中列为 TTS 3 元/万字符、ASR 1 元/小时；这是人民币后付费，不是 AFP 抵扣系数。文本模型超额价格另走普通在线推理价表，不能用套餐的平均单价反推。[4]

“只用套餐、不额外扣费”的检查单​

  • 入口：只使用对应套餐与协议的 Base URL。
  • 密钥：区分 Coding 个人、Agent 个人和企业席位 Key；普通方舟 Key 的资源权限按需收窄。[18]
  • 模型：模型 ID 必须出现在当前套餐允许范围内，媒体能力同时检查档位。
  • 模型超额开关：Agent Plan → 超额后付费管理 → 模型，逐项检查为关闭。[5]
  • Harness 超额开关：还要检查 Harness 页签及相应卡片；模型开关关闭，不代表所有配套服务都已关闭超额。[5]
  • 客户端 fallback：不要在限额或报错后自动改用普通按量入口。这是客户端侧的独立控制。
  • 自动续费：如果不希望到期继续扣月费，要另外关闭自动续费；它与超额后付费完全不同。[2][24]
  • 其他资源：检查是否另行开通过普通模型、存储或数据库服务。关闭套餐超额，不等于整个云账号没有其他计费项目。

如果已在使用带数据的 Harness，先读它的停用与数据保留规则；不要为了“省钱”直接关闭抵扣或停服务。[10]

核对用量时也要容忍正常的数据延迟：Agent Plan 文档注明模型调用明细可能延迟 0.5—1 天，超额用量只是预估，最终以账单为准。即时看不到用量，不是“这次免费”的证据。[2]

QPM、RPM、TPM 和周期额度不是一回事​

常说的 QPM 是每分钟查询数；火山相关文档常用 RPM 表示每分钟请求数，TPM 表示每分钟 token 数。图片、视频和实时连接还可能有自己的单位和并发限制。[21][23]

限制约束的对象不能据此推出什么
RPM每分钟请求数一次长请求能消耗多少 token
TPM每分钟 token 数每月总额度和请求数
并发连接 / 任务数同时在途的工作总套餐用量
5 小时 / 周 / 月额度对应周期累计消耗每分钟吞吐保证
日额度 / TPD特定能力的每日上限对所有模型都适用相同规则

本次核查没有找到可可靠引用的个人 Coding / Agent 套餐固定 RPM、TPM 数字表。 Agent Plan 概览只给出 Small 建议单项目、Medium 建议 1—2 个项目、Large / Max 建议 2 个以上项目的使用强度。这不是“并发线程数”或“每分钟请求数”的承诺。[1][2]

火山公开的 ListModelRateLimit 管控接口可以查询账号基础模型的 CurrentRateLimit.Rpm、Tpm、默认配额、TPD、内容生成并发及实时连接限制；但其契约没有说明这些数值就是 /api/coding、/api/plan 的专属配额。因此，它适合补充账号排查，不能直接把普通模型配额贴成套餐 SLA。[23]

遇到 429，应先看具体错误码：AccountRateLimitExceeded 指向 RPM/TPM，带 5 小时、周、月信息的 QuotaExceeded 指向周期额度，ServerOverloaded 指向服务负载。只看到 HTTP 429 就立即升套餐、充值或打开超额，可能没有解决真正的问题。[21]

用 AK 做只读预检，不必先试一条付费推理​

API Key 解决模型工具怎么调用；AK/SK 解决账号和资源怎么管理。两类凭据不要混在一起。[6][18][33]

目前已有公开管控 API 能完成相当一部分预检。以下是文档能力，不是本次账号调用结果：

要确认的事项公开接口能得到什么、还缺什么
当前凭据是谁GetCallerIdentity主账号 ID、身份类型与标识；不能据此断言拥有所有资源权限
买了什么套餐GetPersonalPlan指定 Plan=AgentPlan 或 CodingPlan，查看档位、状态、起止时间、AutoRenew
当前公共套餐模型清单ListArkAgentPlanModel、ListArkCodingPlanModelAgent 可指定个人/企业版本；模型列表不等于该账号已购买该档位
Agent 个人额度GetAFPUsage5 小时、日、周、月的 Quota、Used、ResetTime
Agent 个人用量明细GetUsageDetails按日/小时、模型和时间过滤，区分 WithinPlan 与 OutsideOfPlan
基础模型限流ListModelRateLimit普通账号模型配额；不自动等同套餐入口配额
现金余额和欠费QueryBalanceAcct余额、欠费等资金字段；不是套餐剩余额度
实际费用ListBillDetail按账期和条件分页取账单，需完整处理分页与统计口径

身份查询见 STS 文档。[32] Ark 套餐和模型列表接口注明只支持 Access Key。[16][17][24] Agent 额度与明细接口也有相同鉴权要求。[19][20] 普通模型限流另见配额接口。[23] 账单与余额则属于 billing 权限域。[34][35]

Ark 管控请求使用 https://ark.cn-beijing.volcengineapi.com/，版本为 2024-01-01；STS 的 GetCallerIdentity 使用 sts.volcengineapi.com、版本 2018-01-01。这些是管理入口，不是前面的模型 Base URL。[24][32]

要执行这轮预检，建议单独授权一个受限 IAM 身份，只允许所需查询，不提供主账号全权 AK，不混入购买、续费、模型开通、密钥轮换等写操作。ArkReadOnlyAccess 是官方预设只读策略之一，但不能仅凭名字保证最新套餐 API、账单和 IAM 查询全部包含其中；应逐项确认实际策略与授权。[36]

“只读”也不是“文档证明免费”的同义词。例如账单接口自身有 5 QPS 限制，但这个限制与模型 RPM 无关。本轮没有执行账号探测，也没有把这些查询接口的收费性质做无依据承诺。[34]

还有两个明确边界：GetAFPUsage / GetUsageDetails 适用于个人 Agent Plan，不能直接拿去宣称 Coding 个人额度可查；GetPersonalPlan 返回自动续费，但文档中没有超额后付费开关字段，不能用 AutoRenew=false 当作已关闭超额的证据。[19][20][24]

购买前还有两件事：数据授权和文档冲突​

个人版与企业版，不只是价格差​

服务专用条款写明：Coding / Agent 个人版的输入输出可以用于模型优化、开发及研究等目的；停止使用只能终止之后的授权，不覆盖已经授权的数据。企业版条款则写明不留存交互数据，不收集和使用这些数据做服务优化。[28]

因此，涉及公司源码、客户材料或未公开研究时，不能只比较月费。先确认自己是否有权把内容用于该授权范围；需要企业条件时，直接核对企业套餐和合同，而不是因为个人套餐便宜就默认合适。

此外，第 2.2 条写明授权限于中国大陆地区，并要求商业使用或直接、间接获得收益前取得书面许可。企业版的数据条件也不能自动推导为后台调用、共享或转售获得授权；采购时应一并确认实际用途。[28]

企业版 Coding 的 Team Lite / Team Pro 为 120 / 600 元每席位每月；企业版 Agent 的 Team Small / Medium / Large / Max 为 120 / 600 / 1,500 / 3,000 元每席位每月，首次默认至少 5 个席位。每个席位对应自己的 Key，不能把一个席位共享给未获分配的同事。[28][29][30]

官方页面不一致时，哪些数字不能替它补全​

本次发现了几处会影响实际使用的口径差异：

  1. Medium 视频权益：Agent 概览顶部说 Small、Medium 不支持视频；同页表格又把即将下线的 doubao-seedance-1.5-pro 标为 Medium 可用。不要基于这个过渡项承诺 Medium 能长期用视频；Seedance 2.0 系列明确应看 Large / Max。[2]
  2. 日额度适用范围：概览先把图片、视频、语音、Harness 放在日/月额度说明中，刷新段落又写日限额仅限视觉，后付费规则则说语音和 Harness 仅在月额度触顶后转超额。实际接入某项能力前应以控制台及其专门文档确认，不能自行统一成一条规则。[2][4]
  3. 固定重置与滚动窗口：概览写每周一、每日零点等重置机制；GetAFPUsage 文档却用“滚动窗口”描述。监控应展示服务返回的 ResetTime，不要自己编一套与服务可能不同的重置算法。[2][19]
  4. 同名模型输出上限：Coding 概览把 doubao-seed-2.1-turbo 写为 64k 输出，Agent 权益表写为 256k。文章不把两个页面抹平成同一配置；具体请求还需核对客户端、入口和模型参数约束。[1][2]
  5. 配套 AI Gateway 的模型：AFP 文档另有“AI Native 应用开发底座”的 AI Gateway 价目，明确说明其中模型不是 Agent Plan 套餐模型。不能把那张表并入套餐可直接选择的模型清单。[10]

最后怎样选，怎样开始​

我的建议是把第一次使用做窄，而不是一次接通所有能力：

  • 主要是个人编码：先看 Coding Lite；实际触顶、且任务强度稳定后再考虑 Pro。不要拿未经验证的固定次数做购买预期。
  • 希望文字、图片、语音和搜索用同一个套餐管理：先看 Agent Small / Medium；需要明确指定 Kimi K3 时注意档位差异。
  • 明确要用 Seedance 2.0 系列视频：从 Large / Max 的权益看起，别赌 Medium 的旧视频过渡项。
  • 需要后台自动化或对外服务：先解决使用授权与普通 API 预算，不通过共享套餐、转发池或改客户端标识规避限制。

选定之后，依次确认：套餐生效 → 正确 Key → 正确协议地址 → 支持的模型 → 关闭不需要的超额与续费 → 检查 fallback → 一条短交互 → 用量和账单复核。

这条顺序比“先把 Key 填进去试试”多几步，但它把能调用、允许调用和怎样计费三个问题分开了。后续扩展到图片、语音、视频或更多工具时，也能沿用同样的检查方法，而不必重新猜每一条请求会花哪里的额度。
