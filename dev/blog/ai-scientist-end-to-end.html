一条 Prompt 到一篇论文？AI Scientist、data-to-paper 与 2026 全链路系统

2026年7月31日 · 阅读需 11 分钟

本文是 AutoResearch 系列的专题 B。若想先看项目分类与选型地图，可从全景总览开始。文中的仓库状态、许可证与动态数据核验于 2026 年 7 月 31 日；项目自报、论文实验与本文判断会分别表述。

输入一句研究目标，几小时后得到实验代码、曲线、参考文献和一篇 LaTeX 论文——这已经不是概念演示。AI Scientist、data-to-paper、Agent Laboratory 与 2026 年的新系统，都已把 literature → idea → experiment → paper 串成可运行的软件。

但“流程走完”与“科学发现成立”之间仍隔着很长的证据链。端到端系统最容易制造的误解，正是把一个外形完整的 PDF 当成这条证据链已经闭合。

先拆开“一条 Prompt 到论文”​

所谓端到端，并不意味着系统从绝对空白开始，也不意味着每一环都同样可靠。不同项目其实接受了不同形式的人类先验：

系统真正的起点主要自动化内容最关键的边界
AI Scientist v1人工准备的实验模板idea、改码、实验、图表、LaTeX、LLM review开放性被模板限制
AI Scientist v2主题描述、代码或数据idea、tree search、实验、写作与 review自由度提高，成功率下降
data-to-paper已有结构化数据假设、统计分析、解释、可追溯稿件面向较简单统计问题
Agent Laboratory人类 idea 与详细 notes文献、实验、报告三阶段协作更像科研助理 workflow
AutoResearchClawtopic、配置与执行环境23-stage 全流程、PIVOT/REFINE、审查、LaTeX2026 新系统，独立复现仍少

这张表也解释了为何不能只比较“覆盖多少步骤”。模板、数据、评价器、算力环境与人工 notes 都是隐含输入；把它们从宣传语里拿掉，才看得见系统真正解决了什么。

AI Scientist v1：模板不是缺点，而是成功条件​

AI Scientist v1 论文和仓库第一次把一条完整管线广泛展示出来：模型提出 idea，检查新颖性，在 NanoGPT、2D Diffusion 或 Grokking 模板中修改 experiment.py，运行实验、生成图表、写 LaTeX，最后再让 LLM 模拟会议审稿。官方还公开了样例论文与每个模板约 50 个 idea 的运行数据；README 给出的典型 API 成本是使用 Claude 3.5 Sonnet 时每篇通常低于 15 美元。

它的关键并不是“LLM 已会任意做科学”，而是模板替系统预先完成了大量研究工程：可运行基线、数据入口、输出格式、绘图脚本、LaTeX 骨架和适合机器读取的实验空间。语言层看似开放，行动空间却被精心收窄。这样做降低了环境故障和评价歧义，也让失败能够被识别。

因此，v1 的模板依赖不只是局限，也是高成功率的来源。换到一个没有稳定 baseline、评价器和实验预算的陌生课题时，“照着同一条 pipeline 跑”并不会自动复制它的效果。末尾的 LLM review 同样只能算内置质量信号，不能替代独立复验或真实同行评审。

AI Scientist v2：去掉模板后，搜索树接管了不确定性​

AI Scientist v2去掉了人工实验模板，引入 experiment manager 与 progressive agentic tree search。多个 worker 可以从不同 draft 出发，生成、调试和扩展实验节点，再由 best-first search 选择值得继续的分支；它的 tree-search 内核建立在 AIDE 之上。项目方还报告了一篇由该系统全流程生成、经 workshop peer review 接收的论文，这是流程自动化的重要里程碑。

更值得注意的却是官方自己写下的限制：有强模板时，v2 不一定比 v1 产出更好的论文；更开放的探索带来更低的成功率。一次完整运行通常持续数小时，实验阶段约 15–20 美元，写作阶段再增加约 5 美元；实际成功还依赖 foundation model、idea 难度、Linux、NVIDIA GPU/CUDA 与文献 API。v1、v2 都会执行 LLM 生成的代码，官方明确要求放进受控 sandbox。

这给出了一个很有价值的反例：科研自由度并不是单调增益。 去掉模板后，系统要同时搜索代码、实验设计、故障修复与叙事空间。树搜索能保存多个候选、避免一条错误路线吞掉全部预算，却不能自动保证问题值得研究、baseline 公平、数据未泄漏，或结论跨 seed 成立。

data-to-paper：最重要的输出不是 PDF，而是 data chain​

data-to-paper从另一端切入。它不主打“从一个宽泛 topic 自主发现”，而是从已有原始数据出发，让 LLM 与规则 Agent 依次完成数据探索、假设、文献检索、分析代码、结果解释和逐段写作。其对应研究发表于 NEJM AI。

这个项目最值得借鉴的是 data-chained manuscript：稿件里的数值可以反向点击，一直追到生成该数字的代码行。它还提供 autopilot/copilot、人工 review、rewind、record/replay 与 API cost 跟踪，并覆写部分统计包以加入 guardrails。相比“reviewer Agent 给了高分”，这种 result-to-code 映射更接近可审计的科研基础设施。

项目方也没有回避边界：当前主要为较简单的数据集和统计假设设计，系统不是 error-proof；稿件必须由领域专家检查，使用者对严谨性、伦理和全文负责；AI 生成稿保留透明水印，不应移除。换句话说，data-to-paper 能提高可追溯性，但 traceable 不等于 correct。错误的分析可以被完整追踪，仍然需要专家判断它为何错误。

Agent Laboratory 与 AutoResearchClaw：workflow 正在变成 research OS​

Agent Laboratory把任务拆成 Literature Review、Experimentation、Report Writing 三阶段，调用 arXiv、Hugging Face、Python 与 LaTeX，并支持 copilot 和 checkpoint。它明确把自己定位为 human researcher 的助手，README 甚至建议写入详细 task notes、指定实验、资源和图表偏好。这种诚实的产品边界很重要：它自动化的是重复劳动，不是把研究者的判断从系统里删除。

2026 年的 AutoResearchClaw则把编排进一步扩成 8 phases、23 stages：从问题分解、文献筛选、hypothesis debate，到 hardware-aware code、sandbox 执行、自修复，再到 PROCEED/REFINE/PIVOT 决策、peer review、claim/citation verification 和 LaTeX export。它提供从 full-auto 到 step-by-step 的多种 HITL 模式，仓库还发布了 55 个开放课题的 ARC-Bench；README 报告 2,699 项测试通过。

这些是值得研究的工程接口，但证据必须分层：仓库中存在的源码、测试与 benchmark manifest 是一层；论文实验是一层；README 中关于跨领域质量、自我进化和“无幻觉引用”的描述又是另一层。AutoResearchClaw 在 2026 年 3 月才首次公开，样例论文和高 star 不能替代跨团队复现，因此更适合视为快速演进的 M2 系统，而不是无人值守的论文生产线。

公开仓库不等于可以复用的开源系统​

端到端系统涉及代码、论文和署名，许可证不能放到部署之后才看。

  • AI Scientist v1/v2：当前均使用 2025 年 12 月版自定义 The AI Scientist Source Code License。许可证包含用途限制，并要求使用该软件生成或传播科研稿件时，以显著、可理解的方式披露 AI 参与。源码可读不等于 MIT/Apache 式开源。
  • AI-Researcher：系统覆盖 reference paper / idea、算法实现、Docker 实验、结果分析和论文，项目论文获 NeurIPS 2025 Spotlight；但本次 checkout 没有 LICENSE。默认著作权仍然保留，不能因为 GitHub 公开就假定可复制、修改或部署。
  • AutoSOTA：仓库有 MIT LICENSE，也公开了 105 个优化结果；其协议包含 onboard、文献调研、改码、回退、resume、guardrail metrics 和独立只读收尾评估，值得借鉴。但仓库提交的 CLI 只有离线 npm tarball，JavaScript 入口被混淆、核心 Python 由 PyArmor 封装，而且文档版本领先于仓库包。结果可以检查，核心决策过程却不能完整审计。
  • data-to-paper、Agent Laboratory、AutoResearchClaw：仓库采用 MIT；EvoScientist、DeepScientist 采用 Apache-2.0。宽松许可证解决的是复用许可，不会自动证明科研质量。

这里的判断不是“非宽松许可证就没有价值”，而是必须准确区分 open source、source-available、无许可证公开源码，以及“外围仓库开源但核心不可读”。

2026 新锐侧栏：从 one-shot 转向长任务与可接管状态​

EvoScientist以 plan、research、code、debug、analyze、write 六类子 Agent 和跨会话 memory/skills 组织 intake → plan → execute → evaluate → write → verify；DeepScientist则强调 local-first、one quest = one Git repo，用 branches、worktrees 和本地 artifacts 保存路线，并允许人随时接管。这两个 Apache-2.0 项目都在 2026 年快速更新。

它们透露出的方向比“再多一个写作 Agent”更重要：全链路系统正在变成可恢复、可观察、可接管的 research OS。不过，新架构与排行榜成绩仍不等于端到端科学有效性；尤其要区分 Deep Research、代码执行 benchmark 与真正的实验复现、主张核验。

为什么一篇 PDF 不是科学发现的完成证明​

一条 pipeline 可以成功编译论文，同时在任意一环失败：引用真实但不支持句子；代码能跑但比较不公平；主指标提高却牺牲 guardrail；单个 seed 偶然胜出；分析数字正确但因果解释过度；内置 reviewer 又读取了 executor 的叙事，形成“自己证明自己”。

更合理的验收对象不是 PDF，而是六道彼此独立的 gate：

  1. 执行 gate：代码在隔离环境中完成，失败、超时和成本都有记录。
  2. 复现 gate：候选在干净 runner、锁定依赖、多 seed 或完整数据上重跑。
  3. 评价 gate：evaluator、test split、预算与 guardrail metrics 对 Agent 只读，防止 evaluator tampering 和 Goodhart。
  4. 来源 gate：每篇引用可定位，且确实支持对应陈述；“文献存在”与“引用相关”分开检查。
  5. 主张 gate：论文每个关键数字回到 artifact、配置、seed、commit 与环境，每个结论不超出这些证据。
  6. 责任 gate：研究者审核问题价值、数据许可、伦理、结论、AI 披露、署名和提交。

因此，评测端到端系统时也不应只数“生成了几篇论文”。更有用的指标是 run completion rate、reproducible improvement rate、独立 evaluator 通过率、unsupported claim/citation rate、人工修复时间，以及失败恢复后的总成本。

现在应怎样接入​

对已有模型服务、GPU、代码仓库和 Overleaf 的团队，最稳妥的路径不是先放开 full-auto，而是分层组合：实验层用固定 evaluator 与隔离 worktree；文献层使用可核验来源；artifact 层保存 patch、日志、环境与原始结果；写作层借鉴 data-to-paper 的 data chain；最后由与 executor 分离的 reviewer 和人类审批。具体的窄闭环合同可参见专题 A，runtime、provenance 与独立审查则在专题 C展开。

AI Scientist v1/v2 适合研究模板约束与开放搜索的取舍；data-to-paper 适合已有数据、强调可追溯草稿的任务；Agent Laboratory 适合人在环的多 Agent 编排；AutoResearchClaw、EvoScientist 与 DeepScientist 适合评估 2026 年的长任务架构。它们都可以进入试验台，但不应直接获得投稿权限。

“一条 Prompt 到一篇论文”在 2026 年已经能生成 paper-shaped artifact；真正稀缺的仍是从问题、实验、原始结果到主张的可验证链条。端到端系统的价值，不是替科学家按下投稿按钮，而是把这条链上的接口、失败与责任暴露出来，让自动化终于有机会被审计。
